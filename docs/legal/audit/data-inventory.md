# Technical privacy audit: data inventory

**Scope:** repository implementation review, 2026-11-27. Not legal advice; counsel should assess applicable Egyptian and other laws. “Implemented” means present in source, not confirmed live in production. No production data inspected.

| Data / activity | Status and evidence | Risk / missing information |
|---|---|---|
| Account identity | Implemented in Adonis user schema: username, email, mobile, full name, governorate, locale, preferences, role/status, verification and login timestamps; `apps/api/database/schema.ts` (`UserSchema`); authentication model `apps/api/app/models/user.ts`. Password uses scrypt hash. | Email/mobile are direct identifiers; governorate and activity can identify/link users. Confirm exact API validation, data minimization, production access and retention. |
| Registration and sign-in | Implemented: password registration/login and mobile OTP flows in `apps/api/app/controllers/auth_controller.ts`; routes `apps/api/start/routes/v1/auth.routes.ts`. OTP routes are explicitly wired to `mobileVerificationDisabled`; signup/login status needs runtime verification. Better Auth social OAuth on public Next app uses Google/Facebook configured providers, cookie state and short session cache: `apps/public-web/src/lib/auth/better-auth.server.ts`; Adonis bridge and identity records in `apps/api/app/services/social_auth_assertion.ts`, `apps/api/app/models/external_identity.ts`, `apps/api/app/models/social_auth_attempt.ts`. | Third parties receive OAuth identifiers/profile claims. No email verification flow found for Adonis accounts; social provider email is not equivalent to verified local email. OTP is disabled in current routes despite UI/docs references. Confirm provider scopes, claim fields, callback retention and production activation. |
| Password recovery / verification | Mobile-based OTP recovery and account verification code paths exist in `apps/api/app/controllers/identity_controller.ts`, `apps/api/app/services/identity_service.ts`; persisted OTP has mobile, purpose, code hash, attempts, expiry, consumption in `apps/api/database/schema.ts`. OTP plaintext logging helper exists at `apps/api/get_otp.ts`; production usage unknown. | OTP exposure if helper is enabled; verify it is dev-only and unavailable in deployed images. No configured outbound email verification evidenced. Confirm OTP sender, throttling and log retention. |
| Guest and registered checkout | Implemented public storefront server actions `apps/public-web/src/lib/commerce/checkout-actions.ts`: email, first/last name, address lines, city, country, phone; shipping/billing address and cart/order submitted to Medusa. Cart ID kept in cookie; signed-in account may be linked through Adonis/Medusa. | Guest checkout data still personal data. Determine whether checkout requires account, guest order access/deletion, address/order retention and whether billing duplicates shipping. No live service verification. |
| Orders, payment, delivery | Medusa owns commerce persistence and checkout; `apps/backend/medusa-config.ts`. Offline InstaPay provider implementation `apps/backend/src/modules/offline-payment/service.ts`; Egyptian EGP path and instructions; no card processor evidenced in configured providers. Shipping options and address validation in `checkout-actions.ts`. | Payment reference/receipt handling and courier disclosures/recipient are not fully established from code. Confirm actual enabled methods, courier integrations, manual InstaPay reconciliation, accounting retention and order deletion constraints. |
| Collector profiles and collections | Implemented profile and collection data in Adonis schemas/models: `apps/api/database/schema.ts`, `apps/api/app/models/user_checklist.ts`, `apps/api/app/models/user_checklist_card.ts`; API includes profile, checklist export and visibility/preferences. | Collection ownership/visibility can reveal interests and trading behavior. Confirm defaults, public fields, indexing/search access and account erasure effects. |
| Reviews, conversations, swaps | Implemented user reviews, conversations/messages and swap deals: `apps/api/app/models/review.ts`, `conversation.ts`, `message.ts`, `swap_deal.ts`; routes `apps/api/start/routes/v1/conversations.routes.ts`, `swaps.routes.ts`; controllers in `apps/api/app/controllers/`. Deal state includes shipping. | Messages and trade/shipping coordination may contain contact/address data and other users’ personal data. No retention, moderation, reporting or deletion schedule identified; establish access controls and post-deal retention. |
| Privacy settings / user rights | Implemented preference read/write and personal-data export/deletion endpoints, `apps/api/app/controllers/identity_controller.ts`; routes `apps/api/start/routes/v1/users.routes.ts`; UI `apps/web/src/pages/AccountSettings.tsx`. Export scheduled for seven-day expiry; cleanup job files `apps/api/app/jobs/PrivacyExport.ts`, `PrivacyExportCleanup.ts`. Deletion anonymizes user and cancels exports, rather than proving full cascade erasure. | Check export completeness across Medusa, CMS, logs, backups and processors; download authorization/token expiry; anonymized references and retention; deletion identity verification and completion reporting. |
| Cookies and browser storage | Adonis session/XSRF cookie configuration `apps/api/config/session.ts`, `shield.ts`; Next storefront cart cookie in `apps/public-web/src/lib/commerce/cart-actions.ts`; Better Auth state/session cookies in `apps/public-web/src/lib/auth/better-auth.server.ts`; Medusa 30-day rolling sessions in `apps/backend/medusa-config.ts`. | Review cookie attributes/domain, production HTTPS/SameSite behavior, consent requirements and expiry. No browser analytics/storage implementation found in sampled application source; verify full dependency/runtime and deployment scripts. |
| CMS/admin data and media | Strapi content and admin accounts; upload plugin stores files in DigitalOcean Spaces-compatible S3, `apps/cms/config/plugins.ts`; database client/config in `apps/cms/config/database.ts`. CMS supports media including images/video/audio/PDF/docs/text. | Public uploads and embedded personal data may persist in media backups/CDN. Confirm access/publication permissions, metadata stripping, lifecycle and region. CMS SQLite is default if env omitted; production config must explicitly set durable DB. |
| Logs and operational metadata | Adonis logger/database/session configs; API access tokens store hash, abilities, use and expiry; `apps/api/database/schema.ts`. Failed/deletion/export audit data and login timestamps are stored. | No complete log inventory, redaction policy, retention, backup expiration or incident process found. Inspect hosting log aggregation and provider retention. |
| Children / age | No age, birth date, parental consent or age gate identified in user schema/routes/UI inspected. | Age eligibility and handling of minors are unknown; collector audience may include children. Product owner/legal counsel must set age policy and safeguards. |
| Cross-border transfers | Code references DigitalOcean Spaces, managed or configured databases, Google/Facebook OAuth, and external catalog/CMS endpoints. `apps/backend/medusa-config.ts`, `apps/cms/config/plugins.ts`, `apps/public-web/src/lib/auth/better-auth.server.ts`. | Source does not establish actual regions, legal entities, subprocessors, transfer terms or production endpoints. Obtain deployment and vendor account evidence. |

Review covered source and configuration definitions for `apps/api`, `apps/backend`, `apps/cms`, `apps/public-web`, `apps/web`, `apps/mcp`, shared packages, schemas/migrations and relevant docs. No production environment, customer data, cloud dashboard, vendor contract, database contents, runtime network traffic or deployment secrets inspected. Environment values intentionally not printed.
