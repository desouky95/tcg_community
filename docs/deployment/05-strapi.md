# 05 — Strapi CMS

Prerequisites: a working Node version supported by the selected Strapi release, PostgreSQL database and credentials, and the monorepo. Strapi is not present yet; this section requires implementation and testing.

1. Check [Strapi's installation requirements](https://docs.strapi.io/cms/installation) and select a stable version compatible with your Node runtime. From the workspace root, scaffold a TypeScript project at `apps/cms` using that version's documented CLI and PostgreSQL option. Pin its dependencies and update the workspace lockfile. Do not commit generated secrets or a local database.
2. Configure `config/database.ts` to use `DATABASE_HOST=db`, port 5432, database `tcg_strapi`, its dedicated role and password. Set the supported application keys, `API_TOKEN_SALT`, `ADMIN_JWT_SECRET`, `TRANSFER_TOKEN_SALT`, `JWT_SECRET`, and any additional secrets required by the chosen release. Generate independent random values and store them in the CMS env file. Set host `0.0.0.0` and the public URL `https://cms.example.com` using that release's documented configuration.
3. Define **Page** (title, unique slug, body, SEO fields), **Banner** (title, optional text, image, link, placement), and **Article** (title, unique slug, summary, body, cover image, publication date). Enable draft/publish; save schema files in version control. Medusa remains authoritative for products, inventory and orders.
4. Build the admin in the image and mount a persistent volume at the actual `public/uploads` directory. Create the first administrator on first launch and secure the account. Configure only the minimum read permissions for published editorial content; keep writes and drafts authenticated. Alternatively use a server-only read-only API token with limited access. Never put an admin token in a `NEXT_PUBLIC_` variable.
5. Implement a server-side Next content client using an internal `STRAPI_URL` and, if using a token, `STRAPI_READ_TOKEN`. Retrieve only published content and required media, validate response shapes, handle CMS failure gracefully, and cache public results for a short bounded period. Update storefront pages to render editorial content with a safe fallback. Do not trust arbitrary HTML without sanitization.

Verification: create a draft and a published item, confirm only the latter is accessible anonymously or with the read token, render it on the site, upload media, recreate the CMS container, and confirm the media remains. Test that CMS downtime does not expose secrets or crash unrelated checkout pages. If content is missing, inspect permissions, the selected Strapi version's response format, and the internal URL.
